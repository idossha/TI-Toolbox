Project overview, predictable batch runs, and a faster guide-first viewer

The new front door summarizes the whole BIDS project. Workflow pages share one visible subject selector and one scheduler-enforced concurrency policy. Run-page 3D panes use a packaged Ernie guide, while the dedicated Viewer loads only when the user asks.

Core product rule Selection is not execution.

Changing a subject, atlas, field, or batch size updates a draft. The server loads or schedules work only after an explicit action.

One project, three levels of attention

Five implementation contracts

R1

Overview replaces Subjects

Rename route, rail, Cmd+1, palette, and landing behavior. Reuse the current readiness matrix, add EEG-net and high-level output facts, and remove Subject Info.

Non-negotiable: one bounded /api/catalog/overview request; Results remains the only detailed output browser.
R2

One terminal, local Clear

Extend the existing shared JobConsole. Clear hides current lines by source/sequence watermark; new lines continue and server logs remain intact.

Evidence: vertical and horizontal scroll geometry, source reset, immutable input, new-line-after-clear.
R3

One subject and batch grammar

Open SubjectsField by default everywhere it applies. Generalize job groups so the scheduler enforces the selected per-subject cap.

Semantic: cap 1 is sequential; cap N permits N concurrent subjects. Group analyses stay one cohort job.
R4

Fixed Ernie workflow guide

Ship lean immutable surfaces, standard nets, and atlas labels behind project-independent guide APIs. Selected research subjects no longer trigger scene rebuilds.

Safety: name-based net/region selection remains; Ernie RAS cannot write another subject's coordinates.
R5

Viewer draft → Load → applied scene

Add Type and conditional subject, simulation, analysis, field, atlas, space, ROI, and custom-path controls. Menu catalog queries are allowed; scene construction is not. Deep links prefill only. A failed Load leaves the previous scene visible.

Contract addition: optional atlas parameter; absent preserves current server-selected behavior.

Current behavior → target behavior

Today

  • Subjects is the landing page.
  • Subject Info duplicates a simpler matrix.
  • Overview counts fan out and stop eager discovery above 25 subjects.
  • Only Pre-processing exposes an enforced subject concurrency cap.
  • Run scenes follow the first selected project subject.
  • Viewer selection changes auto-fetch and auto-load.
  • Terminal scroll exists; Clear does not.
→

After

  • Overview is the project-level front door.
  • One aggregate response powers complete presence and counts.
  • Results owns every output detail.
  • Every per-subject workflow has the same server-enforced cap.
  • Run scenes stay on one packaged Ernie guide.
  • Viewer changes remain drafts until Load.
  • Every interactive console shares local Clear.
