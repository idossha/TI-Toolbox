# Release v3.0.0

**Release Date**: unreleased

v3 replaces the PyQt5 GUI with an **Electron desktop application** and the two-image Docker stack
with a single streamlined image. There is no X11 anywhere, FastSurfer replaces FreeSurfer
`recon-all` for segmentation, and viewing happens in [Tetravox]({{ site.baseurl }}/wiki/visualizers/)
inside the app window instead of Freeview and Gmsh as separate X11 programs.

The science is the same `tit` code it always was — the desktop app and a script run the identical
jobs — but **eight defects in the shared scientific core were found and fixed in this release**.
If you hold 2.x results, read
[Scientific corrections from v2.x to v3.0.0](https://github.com/idossha/TI-Toolbox/blob/main/docs/dev/SCIENTIFIC-CORRECTIONS.md)
before you reuse them, and see [Upgrading](#upgrading-from-2x) below.

See [Desktop Application]({{ site.baseurl }}/wiki/desktop-app/) for how the pieces fit together and
the [Wiki]({{ site.baseurl }}/wiki/) for a page per workflow.

#### Additions

- **The desktop application** — an Electron shell that starts the container and loads the UI it
  serves. Docker Desktop (macOS/Windows) or Docker Engine (Linux) is the only prerequisite.
- **[Overview]({{ site.baseurl }}/wiki/overview/)** — a project landing page: one row per subject,
  one dot per artefact, and a per-stage readiness verdict, aggregated server-side across the whole
  project. There was no project-wide view in 2.x.
- **[Jobs]({{ site.baseurl }}/wiki/jobs/)** — every long-running thing is now a job with a record:
  state, stage, elapsed time, CPU and memory, live console, artifacts and a named failure category.
  There was no job registry in 2.x.
- **[Notebooks]({{ site.baseurl }}/wiki/notebooks/)** — Jupyter inside the app, on the container's
  SimNIBS Python, with a seeded worked example that resolves *your* project.
- **[Pipeline]({{ site.baseurl }}/wiki/pipelines/)** — a canvas: wire pre-processing, an optimizer,
  the simulator and the analyzer into one graph, run it as one job group, or export it as a notebook.
- **[Results]({{ site.baseurl }}/wiki/results/)** — one subject-first outputs browser, with
  simulation reports rendered inline instead of in your OS browser.
- **Per-job tables on Simulator, Optimizer and Analyzer** — one row is one job, with its own subject,
  montage/method and target; **Duplicate** is the gesture for "same job, another subject". A run page
  submits its whole table as one request and says how many groups it made.
- **Free-hand electrode placement, folded into the
  [Simulator]({{ site.baseurl }}/wiki/simulator/)** — select a row, click the subject's own scalp in
  the 3-D pane, and the row takes that point in subject millimetres. This is the only pane that draws
  the selected subject; the others draw a packaged guide head.
- **Optimizer is one page** — Flex and Ex are two *methods* in a column, not two screens;
  `flex_adaptive`, `flex_pareto` and `mex` are derived from the focality mode and the electrode
  count. New: a search-cost read-out, and a leadfield precondition strip with an ETA on **Generate**.
- **Settings ▸ Optional tools** — Source, Cluster permutation, NIfTI group averaging, Nilearn visuals
  and Quick Notes are switched on per project; each then appears in the rail and runs as a real job
  rather than on the UI thread.
- **Settings ▸ Viewer engine** — the viewer can be updated without updating the toolbox: version,
  protocol, source, sha256-verified installs, and one-click rollback to the bundle the image shipped.
- **Single image, `idossha/ti-toolbox:<ver>`** — SimNIBS 4.6, FastSurfer (`--seg_only`, checkpoints
  pre-downloaded), the desktop UI and the Tetravox embed are all baked into one image. After the
  slimming pass (gmsh, PyQt5, TMS coil models, neovim and the build compilers removed) it is
  **≈ 2.3 GB to download, ≈ 9 GB unpacked on disk** (2.32 GB content / 8.93 GB disk, measured
  2026-09-07 on image `853220d5`), down from 6.66 GB content / 21.3 GB before slimming and from a
  2.5.0 stack of `idossha/simnibs` (6.15 GB) plus `ti-toolbox_freesurfer` (21.9 GB). There is no
  `pip install` at container start.
- **FastSurfer segmentation** — a new, much faster pre-processing stage (`run_fastsurfer`) producing
  a DKT-atlas parcellation in `derivatives/fastsurfer/`, replacing FreeSurfer `recon-all` for the
  segmentation this toolbox needs.
- **Tetravox Embed viewer** — the 3D/volume viewer renders inside the app's own window (WebGL2 + WASM
  on the host GPU, driven by a `postMessage` protocol) instead of launching Freeview/Gmsh as separate
  X11 applications.
- **Docker Engine API stack** — the desktop app drives Docker entirely through its Engine API (image
  pull with progress, container create/start, health check, log streaming, stop) instead of shelling
  out to the `docker compose` CLI; `docker context inspect` is the only remaining CLI use, for engine
  discovery.
- **Three documented ways to run v3**, all landing on the same container-served UI: the desktop app;
  `tit launch --project <dir>` from a `pip install tit` or `./loader.sh` in a clone, for servers
  and SSH sessions with no Electron; and `npm run dev` in `desktop/` to run unreleased code from
  source. See the [Installation Guide]({{ site.baseurl }}/installation/).
- **Offscreen end-to-end test harness** — Electron e2e tests run headless/offscreen by default, with
  a quiet-check wrapper that asserts no window reaches the screen, plus a browser-mode leg that
  drives the UI with no Electron bridge.
- **A v3 release workflow** — `.github/workflows/release-v3.yml` builds and smokes the image, builds
  and verifies **unsigned** installers for macOS arm64/x64, Windows x64 and Linux x64, creates the
  GitHub Release only after that validation is green, and then publishes signed and notarised
  artifacts. A `plan` job hard-fails when `tit/__init__.py`, `version.py`, `desktop/package.json` and
  the compose image-tag default disagree with the pushed tag; `dry_run` exercises everything up to
  the release without pushing an image or signing anything.

#### Changes

- **Exposure metrics follow Cassarà et al. 2025 for shared carriers** — `hf_peak` and `hf_sar` now
  respect `montage.channels`, summing same-carrier fields **coherently as vectors** and combining
  across carriers incoherently (SAR addition), which is the rule the envelope path already used.
  Montages with `channels = None` — every montage built by the 2.x default independent-dyad path —
  are bit-identical. See [SCI-07](#scientific-corrections) below.
- **Focused 3D previews** — **Simulator / Optimizer / Analyzer ▸ Scene** use only the visualization
  viewport and restore separate Skin and Grey matter opacity sliders. The dedicated Viewer keeps its
  full controls; saved scientific configurations are unchanged.
- **Consistent workflow controls** — subject checkboxes and sliders have keyboard-readable names,
  long dropdown choices stay inside their pane, and primary actions and blocked-action reasons use
  the shared layout in both themes.
- **Tabs preserve your work** — switching between Pre-processing, Simulator, Optimizer, Analyzer and
  Viewer retains each tab's draft, subject selection, section state, scroll and live 3D view for the
  open project session. Returning to a tab no longer rebuilds its viewer or resets its camera.
  Project switching starts a fresh session.
- **Config field rename:** `PreprocessConfig.run_recon` → `run_fastsurfer` (an incoming `run_recon`
  is still accepted as a deprecated alias, with a warning); `parallel_recon`, `parallel_cores` and
  `run_subcortical_segmentations` are dropped with no replacement — thalamic-nuclei and
  hippocampal-subfield segmentation have no FastSurfer equivalent.
- **Capabilities:** `x11_display`, `freeview`, `gmsh` and `freesurfer` (as a capability flag;
  `has_freesurfer` on a subject's info is unaffected) are removed from `GET /api/capabilities`;
  `tetravox_embed {available, version, protocol}` and `fastsurfer` are added.

#### Removals

- **The PyQt5 GUI (`tit/gui/`)** — deleted, along with its extension framework, its Qt dialogs and
  the `GUI` shell command. The container ships no Qt at all: PyQt5, `simnibs_gui` and gmsh are
  stripped from the image. The [historical page]({{ site.baseurl }}/wiki/gui/) is kept for reference.
- **The legacy 2.x launcher** — replaced by the desktop app and by `tit launch`.
- **X11 everywhere** — no `/tmp/.X11-unix` or `.Xauthority` mounts, no `DISPLAY`, no `xhost`, no
  XQuartz or VcXsrv setup on any platform.
- **The separate FreeSurfer image** — `recon-all`, the thalamic-nuclei and hippocampal-subfield
  segmentation stages, the `freesurfer` compose service, the `freesurfer_data` volume and the
  FreeSurfer license plumbing for the core workflow are all removed. Existing
  `derivatives/freesurfer/` outputs on disk keep working: readers accept both FastSurfer and legacy
  FreeSurfer outputs.
- **Freeview and Gmsh launchers** — including the `/api/viewers/{freeview,gmsh}` server routes and
  their `_require_x11` capability gate. **gmsh is no longer in the image.**
- **`dockerode` and CLI-driven Docker orchestration** in the desktop app, replaced by the
  dependency-free Engine API client above.
- **The Subject Info panel** — its facts are the [Overview]({{ site.baseurl }}/wiki/overview/)
  page's; an existing project `settings.json` that still names it still loads.
- **The standalone Electrode Placement extension** — folded into the Simulator (see above).

#### Scientific corrections

An external audit of the shared scientific core on 2026-09-07 found six defects in the statistics
engine and the field analyzer; two further items (SCI-07, SCI-08) were found in the same pass. All
were reproduced independently in this repository, fixed and pinned by tests.

| | What was wrong | Affected | What to do |
|---|---|---|---|
| SCI-01 | Two-sided / left-tailed cluster testing merged touching opposite-sign clusters and built its null with `max()` of *signed* masses, selecting the cluster closest to zero rather than the most extreme | 2.2.3 – 2.5.0 | **Re-run** `two-sided` and `less` analyses; there is no rescaling. `alternative="greater"` is unaffected |
| SCI-02 | Group NIfTI stacking accepted equal-shape images with different affines | 2.3.0 – 2.5.0 | **Re-run** if subject affines differed; a common grid was and is the normal case |
| SCI-03 | Voxel focality volumes divided by 100 instead of 1000 | 2.3.0 – 2.5.0 | `focality_*_area` from voxel analyses is **10× too large**; rescalable. Mesh focality is unaffected |
| SCI-04 | Sampled permutation p-value was `b/m`, so `p = 0` was reachable | 2.2.3 – 2.5.0 | Now the Phipson & Smyth `(b+1)/(m+1)` estimator; **rescalable** |
| SCI-05 | Voxel volume and spherical-ROI distance came from the header zooms, not the image affine | 2.3.0 – 2.5.0 | Wrong only for sheared affines; **re-run** those |
| SCI-06 | A zero-variance contrast was reported as `t = 0, p = 1` | 2.2.3 – 2.5.0 | Perfectly separated voxels were reported as null; **re-run** |
| SCI-07 | `hf_peak` / `hf_sar` ignored `montage.channels`, treating phase-locked same-carrier fields as independent carriers | 2.5.0, and only for montages declaring `channels` | `hf_sar` was a **lower** bound, so safety headroom was overstated; **recompute** the two maps from the stored per-pair fields — no FEM re-run needed |
| SCI-08 | The K ≥ 2 envelope was evaluated as a difference of two near-equal square roots | 2.4.0 – 2.5.0 | Precision loss only at `Q ≪ P`, below the FEM noise floor; **no action** |

Per-finding detail — what changed, by how much, how to tell whether your results are among them, and
the commit and tests for each fix — is in the
[scientific-corrections record](https://github.com/idossha/TI-Toolbox/blob/main/docs/dev/SCIENTIFIC-CORRECTIONS.md),
which also lists what the audit checked and found **unchanged**, and sets out the exposure-metric
formulas and their Cassarà et al. 2025 limits.

#### Fixes

- **Preview failures stay readable** — a missing or failed 3D renderer no longer loops through silent
  reloads; retry is explicit and retains your surface-opacity settings.
- **Cortical atlas previews load again** — fixed a mesh-index lookup that prevented the atlas surface
  from building. Server build errors now remain readable until you explicitly retry, instead of
  appearing to build indefinitely.
- **`channels` must partition `fields`** (`tit.calc`) — a field index no channel referenced was
  silently dropped, so the envelope described a different montage from the one passed. It now raises,
  naming the unused indices.
- **`hf_peak` exactness is queryable** (`tit.fields.hf_peak_is_exact`) — above 8 carriers the
  direction sweep returns a lower bound on the true worst-case peak, which was documented but not
  exposed.

#### Upgrading from 2.x

- **Check your existing results first.** Read the
  [scientific-corrections record](https://github.com/idossha/TI-Toolbox/blob/main/docs/dev/SCIENTIFIC-CORRECTIONS.md)
  and the table above. In short: **re-run** cluster-based permutation results computed with
  `two-sided` (the default) or `less`; **rescale** voxel `focality_*_area` by 1/10 and any
  `p = 0`; **recompute** `hf_peak`/`hf_sar` for montages that declared `channels`; everything else
  stands. `TI_max`, `TI_avg` and `TI_normal` are unchanged.
- **Install the desktop app** and remove the X11 server you installed for 2.x — XQuartz on macOS,
  VcXsrv on Windows. Nothing in v3 uses it.
- **The image name changed.** v2 pulled `idossha/simnibs:<ver>` (plus a FreeSurfer image); v3 pulls
  the single `idossha/ti-toolbox:<ver>`. The old images can be removed once you have moved over.
- **Your project directory is unchanged.** v3 reads the same BIDS layout and the same
  `derivatives/SimNIBS/`; existing head models, simulations and optimizations are picked up as they
  are, and existing `derivatives/freesurfer/` outputs still read.
- **Scripts keep working**, with one rename: `PreprocessConfig.run_recon` → `run_fastsurfer`, and
  `parallel_recon` / `parallel_cores` / `run_subcortical_segmentations` are gone. The `tit.calc`
  three-function API is as it was in 2.5.0.
- **Segmentation is different, not just faster.** FastSurfer gives you a DKT-atlas parcellation;
  thalamic-nuclei and hippocampal-subfield segmentation have no FastSurfer equivalent and are not
  part of v3. Existing FreeSurfer outputs for those subjects remain readable.

#### Known issues

- **The Docker Hub image for this version is not published yet.** `release-v3.yml` has never run;
  building the image also requires the Tetravox embed asset, which arrives with Tetravox PR #35 and
  its `v0.3.12` tag. Until both land, the packaged app has no image tag to pull, and the supported
  way to run v3 is `npm run dev` from a clone with a locally built image.
- **The packaged app's first launch has not been verified end to end.** Only macOS arm64 has been
  packaged and verified locally; signing and notarisation have never been exercised on this branch,
  and steps that build and label an installer cannot prove it *runs*.
- **App and image must be in lockstep.** The desktop app is a shell that loads the UI from the
  container, so it is useless if the image tag baked into its compose default does not exist on
  Docker Hub. Do not mix a v3.0.0 app with another version's image.
- **`mex` "force left/right symmetry" raises `ValueError`** for SimNIBS's own
  `<sid>_leadfield_<net>.hdf5` naming, because `tit/opt/mex/mex.py` strips `_leadfield` as a suffix
  when the net name comes after it. Use a leadfield named so that the split succeeds, or leave
  symmetry off.
- **Job re-adoption does not survive a server restart.** The job manager keeps a child pid in memory
  only, so a reload can leave a finished job at `running`/`stalled` with its dependants queued behind
  it. `POST /api/jobs/{id}/force` is the escape hatch and lands the job in `lost`.
- **The `cluster-permutation` job on small demo datasets** can exclude every voxel as degenerate; it
  now says so rather than raising a numpy traceback.
