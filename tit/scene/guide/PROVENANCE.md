# Guide scene — provenance and licence

Everything in this directory is **derived data**, generated by
`tit/scene/guide_build.py` from one head model and then frozen. Nothing here is
rebuilt at runtime, and no source dataset is redistributed as such.

## Source

| Field | Value |
|---|---|
| Dataset | SimNIBS **example dataset**, subject `ernie` (T1/T2, charm head model) |
| Upstream | <https://github.com/simnibs/example-dataset> (releases) |
| Local copy used | `/Users/idohaber/datasets/000`, `derivatives/SimNIBS/sub-ernie/m2m_ernie` |
| Head mesh | `ernie.msh`, 174 MB |
| Generated | 2026-09-05; rebuilt 2026-11-07 in `idossha/ti-toolbox:v3.1.3` (SimNIBS 4.6) with this checkout mounted at `/ti-toolbox` |

The same release archive (`v4.1/simnibs4_examples.zip`, sha256-pinned) is the sole source of the
**example-data store, which lives in its own repository**:
<https://github.com/idossha/ti-toolbox-example-data> (release `v1`) — raw T1/T2 NIfTIs
byte-for-byte and one `m2m_<id>.tar.gz` per head model, each asset named by its own sha256 — which
`tit.examples` fetches into a user's project on request (catalogue in
`tit/examples/catalog.json`; that repository's `scripts/` stages and publishes); every asset
carries the GPL-3.0 licence of the dataset it is derived from.

## Licence, and whether redistribution is permitted

**Yes, it is permitted.** The SimNIBS example dataset is published in the
`simnibs/example-dataset` repository under the **GNU GPL v3** (`GPL-3.0-or-later`) (the repository's
own `LICENSE` file is GPL-3.0; GitHub reports the repository licence as
GPL-3.0). TI-Toolbox is itself GPL-3.0, so shipping GPL-3.0 derived assets
inside it is licence-compatible: the combined work stays GPL-3.0, and the
attribution below is the credit the licence requires.

Two neighbouring SimNIBS datasets are **not** covered by that and are
deliberately not used here, because their terms are non-commercial and would
restrict what a TI-Toolbox installation may be used for:

* **Ernie Extended** (MRI+CT extracephalic head model) — CC BY-NC 4.0;
* the **non-human primate** head models — CC BY-NC 4.0.

If SimNIBS ever re-licenses the plain example dataset in a way that forbids
redistribution, the substitution is a one-line change to the generator's
`--project/--subject` arguments: the `/api/guide/*` contract, the manifest
shape and the desktop pane name no subject at all, so another redistributable
reference anatomy (an MNI152-derived head, say) drops in without any API
change.

## What was derived, and what was not

Packaged (see `manifest.json` for exact sizes and SHA-256 of every file):

* `surfaces/skin.{tvsc,gii}` — the scalp, tag 1005, oriented outward and within the
  §S3 budget (≤ 150 000 triangles and ≤ 3 MB per TVSC1 payload);
* `surfaces/gm.tvsc` — the cortex, the whole `lh`/`rh.central.gii`, 617 574 triangles;
* `surfaces/subcortical.{tvsc,gii}` — 17 named deep-brain regions extracted
  offline from the same Ernie `segmentation/labeling.nii.gz` using its full native
  affine, with CSF, ventricles, cortex and white matter excluded. The matching
  label payload retains original CHARM label IDs and LUT names/colours. Source
  and LUT SHA-256 values are recorded in the manifest. Generated 2026-09-14;
  no subject volume is read or transformed when this guide is requested;
* `labels/<atlas>.tvsc` — per-vertex atlas labels on that cortex, for DK40, a2009s and
  HCP_MMP1, from `subject_atlas` on this head's own `sphere.reg`;
* `legends/<atlas>.json` — the label → region id/name/colour legend;
* `nets/<net>.csv.json` — the standard EEG nets' electrode names and positions.

Not packaged, on purpose: the `m2m_ernie` directory itself, the head mesh, the
T1/T2 volumes, the label volume `labeling.nii.gz`, and the `.annot` files. A
guide is an anatomical legend for choosing *names*; none of those are needed to
choose one.

## Coordinates

Every position here is in the guide head's own millimetres, declared as
`"space": "guide-ras"` — **never** `"subject-ras"`. A click on this anatomy may
name an electrode, a channel or a region; it may not produce a coordinate for a
research subject's configuration, because that coordinate would be wrong in a
way no later validation could detect.

## Regenerating

The `m2m_ernie` in Dataset 000 has no `segmentation/`, and the eight nets above are fewer than it now holds. In a
scratch project in the container: copy that `m2m_ernie`, add `labeling.nii.gz` and `labeling_LUT.txt` (the head model's own,
sha256 in `manifest.json`), remove the other nets from `eeg_positions/`, and run `subject_atlas` for each atlas. Then:

```bash
for a in a2009s DK40 HCP_MMP1; do
  subject_atlas -a $a -o <m2m>/segmentation <m2m>
done
simnibs_python -m tit.scene.guide_build --project <scratch> --subject ernie --out /ti-toolbox/tit/scene/guide
```
