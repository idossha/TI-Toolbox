# Source: FreeSurfer's own `distribution/FreeSurferColorLUT.txt`
# (https://raw.githubusercontent.com/freesurfer/freesurfer/dev/distribution/FreeSurferColorLUT.txt,
# fetched 2026-09-03), the section headed "Labels for thalamus parcellation using histological
# atlas (Iglesias et al.)" -- ids 8103-8136 (left) / 8203-8236 (right). This is the FreeSurfer 7.x
# LUT for `ThalamicNuclei.v13.T1.mgz` / `ThalamicNuclei.v13.T1.FSvoxelSpace.mgz`, produced by
# `segmentThalamicNuclei.sh` in a `recon-all` run. Verified voxel-for-voxel against sub-ernie's
# real `ThalamicNuclei.v13.T1.mgz` (all 48 label ids present resolve to a name here) --
# see tests/test_atlas.py::TestThalamicNucleiLut.
#
# Reference: Iglesias JE, Insausti R, Lerma-Usabiaga G, Bocchetta M, Van Leemput K, Greve DN,
# van der Kouwe A, Fischl B, Caballero-Gaudes C, Paz-Alonso PM. A probabilistic atlas of the
# human thalamic nuclei combining ex vivo MRI and histology. NeuroImage 183:314-326 (2018).
# https://doi.org/10.1016/j.neuroimage.2018.08.012
#
# NOT sourced from the per-subject `ThalamicNuclei.v13.T1.volumes.txt` sidecar some
# `recon-all` outputs carry next to the atlas: that file lists nucleus names in a fixed but
# non-numeric order (grouped anatomically, not by label id) that does NOT line up 1:1 against
# a given subject's sorted unique voxel-label ids -- confirmed against three real subjects'
# derivatives (sub-ernie, and two others outside this repo): the set of ids actually carrying
# voxels varies per subject (small nuclei such as Pc/id 8117 and Pt/id 8119 are each absent in
# some subjects and present in others, independently), so naively zipping the sidecar's name
# order against a subject's own sorted id list produces silently wrong pairings (e.g. it would
# read id 8103 as "LGN" here, when the correct name is "AV"). This fixed table is the
# subject-independent id -> name mapping FreeSurfer itself uses and is the only reliable source.
#
